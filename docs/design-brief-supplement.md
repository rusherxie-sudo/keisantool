## 需求一 · 「多字段表单」布局变体（解决巨型输入框不适配的问题）

### 问题
你给的 A 档输入框 `.input-box` 是 **32px 超大数字 + 单位贴在框内**——对"只有 1～2 个核心输入"的工具（消費税、BMI）非常惊艳。
但我们有一批工具一屏需要 **5～15 个输入字段**：

| 工具 | 日文名 | 典型字段（举例） |
|---|---|---|
| kokuho | 国民健康保険料計算器 | 都道府県・市区町村／世帯人数／加入者ごとの年齢区分／前年所得（複数人）／介護該当 など 10+ |
| kotei-shisan | 固定資産税計算器 | 土地評価額／家屋評価額／住宅用地特例／新築軽減／都市計画税の有無 など |
| calorie | カロリー・基礎代謝計算器 | 性別／年齢／身長／体重／活動レベル／目標（PFC） |
| kyuyo | 給与・時給・残業代計算器 | 基本給 or 時給／所定労働時間／残業時間／深夜・休日時間／各種割増率 |
| saniku | 産休・育休計算器 | 出産予定日／標準報酬月額／就業形態／復職予定日 など複数の日付・金額 |

这些工具如果全用 32px 巨框，**表单会长到要疯狂滚动**，移动端尤其灾难。

### 要交付的布局/组件
在**已有的 `.calc-card` 内部**新增一套"紧凑表单"形态（与 A 档巨型输入框并存、互不替换）：

1. **紧凑输入组件**（暂命名 `.field`）：
   - 高度约 **48–52px**，字号 **16–18px**（不是 32px）。label 在输入框**上方**（紧凑、左对齐）。
   - 支持后缀单位（円／%／cm／kg／時間 等），样式与 `.input-box__affix` 一致但缩小。
   - 全部状态：默认 / focus（用 `--cat-color` 描边）/ 错误（用 `--danger`）/ 禁用 / 带 placeholder。
2. **多列表单网格**：桌面 ≥1024px 下字段可 **2 列（必要时 3 列）并排**；768px 降为 2 列；375px 单列。请给出网格规则（哪些字段全宽、哪些半宽）。
3. **字段分组**：长表单要能分成若干**段**（段标题/细分隔线/可选的轻底色分组），例如国保的「世帯情報」「所得情報」「介護保険」分段。请给分组容器样式（暂命名 `.field-group` + 段标题 `.field-group__title`）。
4. **下拉 select / 单选按钮组** 的紧凑版（沿用你已有的 `.choice` 胶囊单选，但适配进多列网格）。
5. **结果区**：沿用你已有的 `.result`（大结果数字 + 明细行）。多字段工具结果明细行通常较多（5～10 行），请确认 `.result__rows` 在行数多时的排版（必要时两列明细）。

### 样板原型（请至少出 1 个）
用 **「国民健康保険料計算器」（kokuho）** 或 **「カロリー・基礎代謝計算器」（calorie）** 做样板——它们字段最多，最能验证紧凑表单+分组+多列网格在 1920/1440/768/375 下的表现。

## 需求二 · 「宽内容展示」布局（解决早见表/多结果并排，非编辑器分栏）

### 问题
你给的 B 档是 **`.layout-wide` + `.split`（左编辑 ↔ 右预览，高度 `calc(100vh - 260px)`）**——这对 Markdown/JSON 这种"编辑器型"完美。
但还有一类工具同样**内容宽、需要大屏铺满**，却**不是"编辑↔预览"双栏**，套 split 会很别扭：

**2A · 早见表 / 对照表型**（输入少，输出是一张大表）：
| 工具 | 日文名 | 输出形态 |
|---|---|---|
| yakudoshi | 厄年チェッカー | 前厄・本厄・後厄の判定 + **年齢早見表**（男女×各年齢の一覧） |
| wareki | 和暦・西暦変換器 | 相互変換 + **元号⇔西暦の対照早見表** |
| rokusei | 六星占術・大殺界計算器 | 運命星の判定 + **今後数年の大殺界カレンダー表** |

**2B · 多结果并排型**（输入一个、同时出多个等价结果）：
| 工具 | 日文名 | 输出形态 |
|---|---|---|
| tani | 単位変換器 | 一つの値 → 長さ/重さ/面積… **複数単位を同時表示** |
| jisa | 時差計算器 | 都市を選ぶ → **世界の複数都市の現在時刻を並べて表示** |
| color-code | カラーコード変換ツール | 色を選ぶ → **HEX / RGB / HSL / 抵抗カラーコードを並べて表示** + 色見本 |

### 要交付的布局/组件
新增一套"宽内容展示"布局（在已有 `.layout-wide` 容器下，作为 `.split` 的**姊妹形态**，命名建议 `.layout-wide` + `.wide-content`）：

- **结构**：顶部一个**横向宽计算卡**（输入区，铺满或居中宽幅，不左右分栏）→ 下方**宽内容区**（表格 或 结果卡片网格）。**不要用 `100vh` 固高**，内容自然高度，下方还能接 howto/FAQ。
- **2A 早见表组件**（暂命名 `.data-table`）：
  - 斑马纹/细边、表头吸附（可选）、**当前命中行高亮**（用 `--cat-tint` 底 + `--cat-color` 强调，例如厄年表里高亮用户所在年龄行）。
  - 数字列用 `IBM Plex Mono`。
  - **移动端（≤680px）**：宽表必须可**横向滚动**（不破坏页面布局），或转为"卡片化堆叠"——请给出你推荐的方案。
  - 全部状态：默认行 / 高亮行 / 表头。
- **2B 多结果并排组件**（暂命名 `.result-grid`）：
  - 网格卡片，每卡 = **小标签（单位/城市/色彩空间名）+ 大数字/大值 + 复制按钮**。桌面 3～4 列，768px 2 列，375px 单列。
  - `color-code` 专属：卡片需带**色块预览**；另需**取色器/色相面板**入口（沿用你上一批组件清单里提到的取色器）。
  - `jisa` 专属：每卡显示城市名 + 当前时刻（等宽）+ 与基准的时差，可考虑昼夜小图标。
  - 复制按钮的"已复制 ✓"反馈态。

### 样板原型（请至少各出 1 个，共 2 个）
- 2A 用 **「厄年チェッカー」（yakudoshi）** 或 **「和暦・西暦変換器」（wareki）**（早见表型）。
- 2B 用 **「単位変換器」（tani）** 或 **「カラーコード変換ツール」（color-code）**（多结果并排型）。
