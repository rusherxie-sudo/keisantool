# keisantool.com 移动优先重新设计方案

> 状态：设计确认稿  
> 日期：2026-06-18  
> 选定方向：方案 1「Clear Pocket Calculator」  
> 目标：先形成可评审设计，不进入实现。

## 1. 背景与目标

keisantool.com 是日本語の計算・変換ツール集合站，核心流量来自 Google 日本自然搜索。用户通常从移动端进入某个具体工具页，带着一个明确任务，例如「消費税を計算したい」「BMIを知りたい」「MarkdownをHTMLにしたい」，完成后很快离开。

本次改版以移动端为第一优先级，同时保证 PC 宽屏不浪费空间。设计目标如下：

- 用户进入工具页首屏即可开始输入，不需要先阅读说明。
- 输入后结果要足够醒目，适合一眼确认。
- 分享模块要靠近结果区，引导用户把结果发给家人、同事或自己留存。
- 首页和分类页要更像“工具入口”，减少营销感，让用户更快找到工具。
- PC 端要适配不同复杂度工具，简单工具紧凑可信，复杂工具宽幅舒展。
- 广告位置保留，但未加载时不显示占位框、不写广告占位文案、不打断体验。

## 2. 视觉方向

选定方向为「Clear Pocket Calculator」：专业、清爽、移动优先，像一个可信赖的手机计算器，而不是一个堆满内容的工具目录站。

### 2.1 设计气质

- 基底使用真白或接近白的中性背景，避免暖米色、奶油色或过强渐变。
- 主要信任色使用清晰的蓝色系，表达“准确、冷静、可靠”。
- 品牌点缀保留少量珊瑚色，用于 Logo 标记、分享引导或关键 CTA，避免页面显得过冷。
- 金额、比例、时间、代码等关键结果使用等宽数字，强化计算工具感。
- 圆角控制在 8-16px，避免过软、过卡通。
- 阴影克制，优先使用留白、分隔线、浅色底和边框建立层级。

### 2.2 字体建议

保留现有可落地字体体系，但调低圆润感的“玩具感”：

- 正文与 UI：`M PLUS Rounded 1c` 或后续可评估 `Noto Sans JP`。
- 数字与代码：`IBM Plex Mono`。
- 字重：标题 800，控件标签 700，正文 400-500。
- 移动端正文基准 15-16px；表单标签 12-13px；结果主数字 36-44px。

## 3. 信息架构

页面类型仍沿用现有结构，不新增不必要页面：

- 首页：全站工具入口。
- 分类页：7 个分类 Hub。
- 工具页：24 个工具页，是本次设计重点。
- 信任/合规页：about、privacy、terms、contact。

全站框架：

- 顶部 Header：轻量 sticky，移动端优先。Logo + 菜单按钮；展开后按分类显示工具。
- Footer：保留合规链接和版权信息，视觉更安静。
- 浮动分享按钮：保留，但从“全站存在”降级为次入口；主分享引导放到结果区。

## 4. 移动端工具页设计

工具页首屏是本次改版的核心。结构按用户任务排序，而不是按 SEO 内容排序。

### 4.1 首屏顺序

移动端首屏顺序：

1. Header：Logo + 菜单。
2. 面包屑：小字号，弱视觉。
3. H1：工具名。
4. 一句说明：只解释能做什么，不写长文。
5. 计算卡：当前模式、输入、选项、结果。
6. 结果分享模块：结果出现后展示。
7. 广告插槽：仅有广告内容时展示。
8. 下一节露出：使い方。

### 4.2 计算卡

计算卡应像手机上的专用工具，不像表单问卷。

- 卡片宽度贴合手机边距，左右留 16-18px。
- Tab 使用横向 segmented control，支持轻扫或横向滚动。
- 主输入框高度约 56px，数字大、易点、易删改。
- 选项按钮最小高度 44px，保证拇指可点。
- 结果框紧跟输入区，结果主数字为页面最强视觉。
- 错误态只在真实需要时出现，提示要具体，不写泛泛“入力エラー”。

### 4.3 简单工具布局

适用于 zeizei、bmi、nenrei、wariai、gasoline 等。

移动端：

- 单列。
- 输入和结果尽量在首屏内完成。
- 说明区、FAQ、相关工具放在结果之后。

PC：

- 采用“计算工作台 + 说明侧栏”的两栏布局。
- 左侧为计算卡，宽度建议 520-620px。
- 右侧为使い方、免責、相关工具的紧凑摘要或目录。
- 页面下方仍保留完整 FAQ 和分享条。

### 4.4 复杂工具布局

适用于 markdown、regex、json、color-code、tani、moji、yakudoshi、wareki、jisa 等。

移动端：

- 不强行左右分栏。
- 编辑器型工具使用“输入 → 输出/预览”的纵向结构。
- 多结果型工具使用结果卡片列表。
- 宽表格使用横向滚动容器，不撑破页面。

PC：

- 使用宽幅单栏或内容自适应工作区，最大宽度建议 1120-1280px。
- Markdown/JSON/Regex 这类编辑器型可使用左右双栏。
- Color/Tani/Jisa 这类多结果型可使用上方输入区 + 下方结果网格。
- Yakudoshi/Wareki 这类表格型可使用上方输入区 + 下方宽表。
- 不再把复杂工具压进 560px 固定窄卡。

## 5. 分享模块设计

分享是本次改版的显性功能，不再只是页尾社交按钮。

### 5.1 结果区分享

每个工具的结果区下方新增“结果分享模块”。默认在有结果后显示。

推荐结构：

- 标题：結果をシェア
- 辅助文案：家族や同僚に送る / 買い物メモとして送る / 結果をあとで見返す
- 主按钮：LINE
- 次按钮：コピー、X、共有
- 复制反馈：コピーしました

复制内容不应只复制 URL，而应复制“结果摘要 + 页面链接”。

示例：

```text
消費税・割引計算器
税込価格：¥1,100
消費税：¥100
https://keisantool.com/zeizei/
```

不同工具可生成不同分享摘要：

- 税金/金钱：主金额 + 明细金额。
- 健康：BMI、判定、目标体重。
- 时间/日期：转换前后时间、日期。
- 开发者工具：转换结果摘要或“ブラウザ内で変換しました”。

### 5.2 移动系统分享

移动端优先使用 `navigator.share`。如果浏览器不支持，则回退到复制链接。

设计表现：

- 支持系统分享时显示「共有」。
- 不支持时显示「コピー」。
- LINE 仍作为主要显性按钮，因为日本移动分享场景高频。

### 5.3 页尾分享条

页尾分享条保留，用于 SEO 内容读完后的二次分享。

- PC：横向按钮组。
- 移动端：紧凑按钮组。
- 页尾分享条视觉弱于结果分享模块。

### 5.4 浮动分享按钮

右下角 FAB 保留，但不应遮挡输入框和结果。

- 移动端当结果分享模块在视口内时，FAB 可降低强调或隐藏。
- 滚到说明/FAQ 区时，FAB 可恢复为快速分享入口。

## 6. 广告规则

广告位置保留，但不做可见占位。

### 6.1 原则

- 结果下方和页面下方保留广告插槽结构。
- 没有广告内容时不显示任何灰框、虚线框或「広告枠」文字。
- 没有广告内容时不强制占用高度。
- 广告加载成功后自然展开。
- 禁止弹窗、插屏、遮挡输入区或遮挡结果。

### 6.2 视觉规则

广告出现时：

- 与内容区保持 20-28px 间距。
- 背景不做强卡片化，避免误认为工具结果。
- 广告区域不影响计算卡和分享模块的优先级。

广告未出现时：

- 页面直接衔接到下一内容区。
- 不产生大块空白。

### 6.3 实现提示

后续实现可采用：

```css
.ad-slot:empty {
  display: none;
}

.ad-slot[data-loaded="false"] {
  display: none;
}
```

如果 AdSense 需要最小高度防 CLS，应只在确认会请求广告时启用高度，不在静态页面默认显示占位。

## 7. 首页设计

首页目标不是宣传，而是帮助用户快速进入工具。

### 7.1 移动端首页

结构：

1. Header。
2. 简短 H1：日本語計算ツール一覧。
3. 搜索/快速筛选入口。
4. 高频工具区：税金、年齢、BMI、カラーコード、単位変換等。
5. 分类分组工具列表。

移动端工具卡建议从当前两列改为更可扫读的列表或“1 列主列表 + 小图标”：

- 工具名为主。
- 一句短描述为辅。
- 图标作为识别辅助，不作为主要视觉。
- 卡片高度稳定，避免不同日文长度导致参差。

### 7.2 PC 首页

PC 首页可使用更宽的分类矩阵：

- 顶部保留简洁 Hero。
- 高频工具横排。
- 分类工具使用 3-4 列网格。
- 每个分类区不做过重卡片容器，使用标题、细分隔线和工具卡建立层级。

## 8. 分类页设计

分类页面向从首页或导航进入的用户，目标是“在一个主题下快速选工具”。

结构：

1. 面包屑 + H1 + 分类导语。
2. 该分类工具列表。
3. FAQ。
4. 其他分类链接。

移动端：

- 工具列表优先单列。
- 分类页不放大 Hero，不占用过多首屏。
- FAQ 默认折叠，避免挤压工具入口。

PC：

- 工具卡 2-3 列。
- FAQ 和其他分类可并排或下方分区。

## 9. 合规页设计

合规页保持安静长文排版。

- 最大文本宽度 680-760px。
- 行高 1.8 左右。
- H2 有明确分隔。
- 不加入营销式图形。
- 分享模块不作为重点。

## 10. 组件规范

### 10.1 Header

移动端：

- 高度 56-60px。
- 左侧 Logo，右侧菜单按钮。
- 展开菜单按 7 个分类分组。
- 分类组使用手风琴。
- 当前页高亮清晰但克制。

PC：

- Header 高度约 64px。
- 分类下拉保持，但减少视觉重量。
- 下拉菜单工具列表要易扫读，图标小于当前版本。

### 10.2 工具卡

移动端工具卡：

- 更偏列表项，而不是大卡片。
- 最小点击高度 56px。
- 图标 32-40px。
- 工具名 15-16px，短描述 12-13px。

PC 工具卡：

- 允许网格卡片。
- 卡片边框轻，hover 才强化边框或背景。
- 避免过强阴影。

### 10.3 表单控件

- 输入高度：简单工具 56px，多字段工具 48-52px。
- 数字输入使用等宽字体。
- focus 使用分类色描边。
- radio/segmented control 最小高度 44px。
- 移动端不使用过小的下拉控件。

### 10.4 结果框

- 结果主数字永远是计算卡内最高层级。
- 明细行使用稳定左右布局。
- 金额增减可使用成功/警告色，但不要满屏红绿。
- 结果出现时可轻微淡入，不做夸张动画。

### 10.5 FAQ

- 移动端默认折叠。
- summary 点击区域至少 48px 高。
- 展开态背景轻微变化。

## 11. 响应式断点

建议断点：

- 375px：核心移动宽度，所有首屏体验必须验证。
- 768px：平板/窄屏，部分列表可变 2 列。
- 1024px：进入桌面布局。
- 1440px：标准宽屏，检查是否浪费空间。
- 1920px：超宽屏，检查内容是否过窄或漂在左侧。

布局规则：

- 移动端先满足任务完成。
- 平板不强行桌面两栏。
- PC 简单工具可以两栏。
- PC 复杂工具必须宽幅。
- 所有固定格式元素使用稳定尺寸，避免结果变化导致布局跳动。

## 12. 可访问性

- 所有输入必须有 label。
- 所有按钮可键盘聚焦。
- focus-visible 清晰。
- 分享按钮有明确文本或 aria-label。
- 颜色对比满足正文可读。
- 移动端不依赖 hover。
- 横向滚动表格要有可见提示或自然滚动区域。

## 13. 不做的事

本轮设计不做以下内容：

- 不改计算逻辑。
- 不新增工具。
- 不改变 SEO 页面结构的核心要求。
- 不使用 React/Vue/Tailwind。
- 不引入大型图片 Hero。
- 不做弹窗广告、插屏广告或遮挡式分享引导。
- 不把工具页做成营销 Landing Page。

## 14. 后续落地顺序建议

后续进入实现时，建议按以下顺序：

1. 重构全局令牌和移动基础布局。
2. 更新 Header、Footer、工具卡、FAQ、广告插槽显示规则。
3. 更新 ToolLayout，支持简单工具与复杂工具两类布局。
4. 更新首页和分类页。
5. 更新简单工具样板页 zeizei。
6. 更新复杂工具样板页 markdown 或 color-code。
7. 把结果分享模块抽成复用组件。
8. 批量套用剩余工具页。
9. 验证 375 / 768 / 1440 / 1920。
10. 构建并部署。

## 15. 验收标准

设计落地后应满足：

- 375px 移动端打开工具页，首屏可以开始输入。
- 输入后结果和分享入口在移动端无需大幅滚动即可看到。
- 未加载广告时页面没有灰色广告占位框。
- 1440px 和 1920px 下复杂工具不再被限制在窄列。
- 首页移动端工具发现路径比当前两列卡片更易扫读。
- 分享模块能复制结果摘要和链接，移动端优先系统分享/LINE。
- 现有 SEO、FAQ、免责声明、RelatedTools 不丢失。
