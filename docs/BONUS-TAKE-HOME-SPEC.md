# 賞与・ボーナス手取り計算器 — 首版规格

立项日期：2026-09-14。状态：2026-09-18首版已上线，提交ef030f7的GitHub／Cloudflare检查与线上算例通过；当前交付范围见下文补充。用户已同意“先做入社反推小实验，同时把奖金到手计算作为第一个独立新工具立项”。

## 需求与页面归属

- 目标任务：知道奖金总额后，核对扣款与实际到手金额，理解上月工资、扶养人数对预扣税的影响。
- 候选 URL：`/bonus-tedori/`；标题方向：`賞与・ボーナス手取り計算｜所得税・社会保険料の内訳`，年度以实际核验支持范围为准。
- 历史证据：仓库 `keywords/opportunities/blue_ocean_keywords.csv` 的2026年7月研究记录中，「賞与 社会 保険 料 計算」估计3,600/月、KD26；「ボーナス 税金 計算」估计2,900/月、KD28。不可相加，不代表2026年9月现量或预计本站点击。
- 近期证据限制：2026-08-15–09-11的GSC披露查询未出现賞与／ボーナス查询；Semrush浏览器占用，最新日本SERP与难度待核验。
- 现有 `/kyuyo/` 是工资与残业计算，`/shakaihoken/` 是月度保险估算，均不是完整奖金计算。首版一个独立工具页，相关页正文互链，不按金额创建批量索引页。

## 首版输入与输出

首版优先服务日本居住、正常在职、提交扶养控除等申告书（甲栏）的员工，使用2026年税额表。将适用范围置于表单前；不把不适用输入计算为0税额。

| 输入 | 用途与约束 |
| --- | --- |
| 奖金支付日、税前总额 | 选择适用税率／保险版本，金额为非负整数円 |
| 上月工资扣社保后的金额 | 与“税后到手”明确区分；直接用于算出率表 |
| 税表口径的扶养亲族等人数 | 解释税表计数规则，不等同家庭人口；超支持范围提示 |
| 奖金社保扣款输入方式 | 首版提供“已知扣款额”模式，输入明细中的社保等金额；自动估算模式须先核验下述保险数据 |
| 奖金计算期间≤6个月／>6个月 | 特殊算法使用6或12的分支 |
| 上月是否有工资、甲／乙栏 | 检测特殊计算或不适用情形 |

结果：奖金总额、社保等扣款、计税基数、采用的预扣税率／算法、源泉所得税及复兴特别所得税、扣除后的金额、适用年度、可复制的明细。已知社保扣款模式不虚构各保险分项；其他公司扣款可独立输入并标明，不参与税基扣除，避免“到手”与实际明细差异不明。

正常分支的最小独立价值是准确查年度奖金预扣率，不能仅提供一个由用户自行填税率的减法器。首版若只支持正常甲栏，对无上月工资、超过十倍、乙栏等必须在计算前显示具体不适用原因及官方算法链接；后续月额表验证完成后再开放相应分支。

## 自动社保估算的准入条件

自动估算是后续开发范围；年度、支付日期、保险种类未核验前，保留已知社保扣款模式即可提供可核验的奖金预扣计算。

- 对照2026年度协会健保各支部健康保险、介护保险及子ども・子育て支援金资料，核验本人负担、适用月与舍入规则；不得复用当前站点全国平均率作为精确明细。
- 核验厚生年金与雇用保险当年度费率、年龄／业务类别、适用范围；雇用保险基数与标准奖金额不可混用。
- 输入同月此前奖金和本保险年度此前标准奖金累计，正确处理两种不同上限。
- 健保组合、资格丧失月、育休免除、年4次以上奖金等复杂条件先明确排除，或切换已知扣款输入模式。
- 年度配置保存官方URL、适用日期、复核日期和独立算例，数据更新后同步验证页面、公式与说明。
