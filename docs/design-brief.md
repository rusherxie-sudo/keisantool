# keisantool.com 全站重新设计 — 设计需求书（Design Brief）

> 这份文档是给 **claude.ai 的设计能力**（或任何 UI 设计工具）看的需求说明。
> 它**只定义"做什么"**：页面、功能、交互结构、技术约束、要交付的文件。
> **不限制任何视觉风格** —— 配色、字形、版式、留白、明暗主题、插画/图标、装饰都由你自由发挥。
> 唯一的硬约束来自 §5 技术架构与 SEO/广告，请务必遵守，否则设计产出无法落地。

---

## 1. 这个网站是什么 / 目标

- **keisantool.com** 是一个**日本語の計算・変換ツール集合站**（日语计算/换算工具大全）。
- 商业模式：靠 **Google 日本自然搜索**引流 → **Google AdSense 横幅广告**变现。
- **界面语言是日文**。本文档用中文写需求说明，但你产出的页面文案应为**日文**（可沿用现有日文内容，或填合理的日文占位文字）。
- 用户画像：从搜索引擎进来、带着**一个明确的单一任务**（"算消费税""查厄年""转单位"）、**用完即走**、**移动端占比高**。

### 设计的成败标准（请围绕这些优化）
1. **即时可用**：进工具页第一屏就能看到输入框并开始算，输入即出结果（不需要点"计算"按钮）。
2. **移动端极顺**：拇指可达、输入舒适、结果醒目。
3. **大屏不浪费**：在 1440/1920 宽屏下版面要充实，不能内容挤在一角、大片空白（这是现版本最大的问题，见 §3.4）。
4. **广告自然**：广告位融入版面、不打断使用、不引起布局跳动（CLS）。
5. **可信赖感**：涉及税金、钱、健康、保险，视觉上要让人觉得专业、可靠、非垃圾站。

## 2. 信息架构（全站页面清单）

全站共 **36 个页面**，但都由**少数几套模板批量复用**，所以请按"页面类型"设计，而不是逐页设计：

| 类型 | 数量 | 说明 |
|------|------|------|
| 首页 | 1 | 全站入口，按分类陈列所有工具 |
| 分类 Hub 页 | 7 | 每个分类一个聚合页 |
| 工具页 | 24 | **网站主体**，每个工具一页 |
| 信任/合规页 | 4 | about（关于）/ privacy（隐私）/ terms（条款）/ contact（联系） |

**7 个分类**：税金・お金 / 健康・身体 / 生活・日常 / 占い・文化 / 文字ツール / 変換・ツール / 開発者ツール

**24 个工具**（每个都有 emoji 图标 + 工具名 + 一句关键词短语）：
- 税金・お金：消費税・割引、固定資産税、国民健康保険料、割合・パーセント
- 健康・身体：BMI・体脂肪率、カロリー・基礎代謝、偏差値
- 生活・日常：出産予定日、厄年、給与・残業代、時差計算、ガソリン代、産休・育休、年齢計算
- 占い・文化：六星占術・大殺界
- 文字ツール：全角半角変換・文字数カウント
- 変換・ツール：カラーコード変換、単位変換、和暦・西暦変換
- 開発者ツール：Base64、JSON整形、URLエンコード、正規表現テスト、Markdown→HTML

## 3. 各页面类型的功能 / 区块需求

### 3.0 全站框架（每一页都有）
- **顶部 Header（吸顶 sticky）**：
  - 左：站点 Logo（文字标志）。
  - 中/右：**按 7 个分类的下拉导航**。每个分类悬停/点击展开下拉菜单，菜单里列出该分类的工具（图标+短名）+ 一条"○○をすべて見る →"（查看该分类全部）链接。
  - 移动端：折叠为汉堡菜单，点开后分类以手风琴形式展开。
  - 需要"当前页高亮"状态。
- **底部 Footer**：合规页链接（关于/隐私/条款/联系）+ 版权信息。
- **右下角浮动分享按钮（FAB）**：固定悬浮，移动端优先调用系统分享。

### 3.1 首页
- **Hero 区**：站点大标题 + 一句话说明。
- **按 7 个分类分区陈列**，每个分区：
  - 分类标题（可点击 → 进入该分类 Hub 页）。
  - 该分类下所有工具的**卡片网格**。每张工具卡 = emoji 图标 + 工具全名 + 一句关键词短语，整卡可点击进入工具页。

### 3.2 分类 Hub 页（7 个）
区块顺序：
1. 面包屑（ホーム ／ 分类名）+ H1（分类标题）+ 一段分类导语。
2. 该分类工具的**卡片网格**（同首页卡片样式）。
3. **广告位**。
4. **该分类的 FAQ**（2~3 组 Q&A，会输出为结构化数据）。
5. "ほかのカテゴリ"（其他分类）的快捷链接（胶囊/标签样式）。
6. **广告位**。

### 3.3 工具页（24 个）—— 全站核心，请重点设计
每个工具页**固定的区块顺序**：
1. **page-hero**：面包屑 + H1（工具名）+ 一句副标题说明。
2. **calc-card（计算交互卡）**：本页的灵魂。用户在这里输入 → **即时显示结果**。
3. **广告位**（紧贴结果下方）。
4. **howto「使い方」说明区**：要点列表 + 注意事项 + **免责声明**（"※ 計算結果はあくまで参考値です" —— 必须有，建议用警示色框）。
5. **RelatedTools（关联工具）**：4 个其他工具的小卡片（内链，SEO 要求每页 ≥3 个内链）。
6. **FAQ**：2~3 组 Q&A。
7. **广告位**（页面下部）。
8. **分享按钮条**：X / LINE / Facebook / はてなブックマーク / 复制链接。

#### ⚠️ 工具有两档复杂度，请给出两套布局规范
- **A 档 · 简单计算器**（多数工具，如消費税/BMI/年齢）：少量输入框 + 一个醒目的大结果框。内容不多。
- **B 档 · 复杂/编辑器型**（markdown / 正規表現 / JSON / カラーコード / 単位変換 / 文字変換 / 厄年）：内容多 —— 需要宽编辑区、左右双栏（编辑↔预览）、大文本框、对照表格、颜色选择器、多单位并排换算等。

#### ⚠️ 现版本最大痛点（重新设计必须解决）
现在 PC 宽屏（1440/1920）用的是"左侧固定 560px 计算卡 + 右侧说明"的两栏布局。对简单工具还行，但**对 B 档复杂工具，内容被挤在左侧 560px 的窄条里，右边一大片空白浪费**，编辑区/多栏内容挤成一团，非常局促。
**请设计一套在大屏下内容自适应、不浪费横向空间的布局方案**（例如：简单工具维持双栏，复杂工具切换为单栏宽幅或更聪明的栅格）。

> 工具页真实区块骨架见本文档 §7 附录（以"消費税・割引計算器"为例）。

### 3.4 信任/合规页（4 个）
- about / privacy / terms / contact。
- 形态：**纯文字长文排版**（H1 + 多个 H2 小节 + 段落 + 列表 + 末尾"最終更新日"）。
- 窄栏、行距舒适、便于阅读即可。contact 页可能含一个简单联系方式区块。

## 4. 需要设计的"组件库"（这是工具页能批量复用的关键）

24 个工具页全靠下面这些可复用组件拼装。**请把每个组件都设计出来，并给出全部状态**（默认 / hover / focus / active / 选中 / 禁用 / 错误，按适用情况）+ 尺寸间距 + 移动端表现：

**全站级**
- 分类下拉导航（桌面悬停展开 / 移动手风琴 / 当前页高亮）
- Footer
- 工具卡片（首页&分类页用）
- 面包屑
- 分享按钮条 + 右下角浮动分享 FAB
- FAQ 条目（Q/A，可折叠或常开，你定）
- 广告位占位（**预留固定最小高度防止布局跳动**；有"结果直下"和"页尾"两种位置）

**计算交互级（工具页内）**
- 计算卡容器（calc-card）
- Tab 切换条（一个工具内多种计算模式，如消費税有"税込/税抜/割引/複数商品"4 个 tab）
- 表单组：标签 + 输入框（**数字输入建议用等宽字体、大字号**；要有 focus 态、placeholder）
- 按钮式单选组（如选税率 10%/8%，选中态明显）
- 下拉 select
- **结果框**：小标签 + **超大主结果数字** + 下方若干明细行（明细行支持正常/红色/绿色等强调色）；结果出现时可带轻微入场动画
- 动态可增删行（一行 = 输入框 + 下拉 + 删除按钮，外加"＋追加"按钮）

**B 档复杂工具专属**
- 代码/文本编辑区 + 预览双栏（Markdown）
- 匹配高亮（正規表現）
- 颜色选择器 / 取色器 + 色值展示（カラーコード）
- 多单位并排换算（単位変換）
- 对照早见表（和暦西暦、厄年等的表格）

## 5. 技术架构（这决定了你该交付什么形态的文件，必须遵守）

- **构建：Astro 静态站点 → 输出纯 HTML/CSS**，部署在 Cloudflare Pages。
- **没有任何 UI 框架** —— 不是 React、不是 Vue、**不用 Tailwind**。页面交互是**原生 Vanilla JS**。
  - 👉 这意味着你的设计落地形态 = **语义化 HTML + 手写原生 CSS**。请不要依赖组件库或工具类框架。
- **样式已经用 CSS 自定义属性（CSS Variables）做令牌**，集中在 `:root`（颜色、字体栈、圆角、阴影等）。
  - 👉 请把你的设计令牌也产出为**一组可直接替换的 CSS 变量**。
- **字体**：现用 `Noto Sans JP`（日文正文）+ `IBM Plex Mono`（数字/代码）。可更换，但必须是 **Google Fonts 可获取、且含日文字形**的字体。
- **响应式**：移动优先。请务必覆盖并交付这 4 个目标宽度的表现：**1920 / 1440 / 768 / 375**。
  - 现有断点供参考（可重新定义）：≥1024px 桌面布局、≤820px 切换移动导航、≤680px 单列。
- **SEO 硬约束**（视觉上要兼容）：每页有唯一 H1、`<title>`、`meta description`、canonical、JSON-LD 结构化数据、面包屑；首屏要快、无渲染阻塞大图。
- **广告（AdSense）**：横幅广告放在**结果直下 + 页面下部**；**禁止弹窗/插屏**；广告位**必须预留高度**，避免内容跳动（CLS）。
- **可访问性**：键盘可操作、焦点可见、文字对比度达标、表单 label 与控件正确关联、隐藏元素不破坏布局。

## 6. 请交付以下文件（按落地优先级排序）

> **交付格式优先级：能直接落地的 HTML + CSS > Figma/图片。**
> 因为本站是手写 Astro + 原生 CSS，拿到 HTML/CSS 可直接移植；纯图片还得二次还原，价值低。

1. **`tokens.css` — 设计令牌**：一组 `:root` CSS 自定义属性，包含完整色板（含语义色：主色/强调/成功/警告/文字/边框/背景等）、字号阶梯、间距阶梯、圆角、阴影、断点、字体栈。目标是能**直接替换**现有 `global.css` 的 `:root` 块。
2. **`global.css`（或等价的全局样式）**：Header / Footer / 页面容器 / 两套布局栅格（简单工具的布局 + 复杂工具的宽布局）/ 各响应式断点的完整 CSS。
3. **可运行的 HTML + CSS 高保真原型**，至少覆盖这 5 个页面（响应式单文件，或桌面+移动两版均可）：
   - ① 首页
   - ② 分类 Hub 页
   - ③ 工具页 · **简单计算器型**（以"消費税・割引計算器"为样板，含 4 个 Tab + 结果框）
   - ④ 工具页 · **复杂/编辑器型**（以 Markdown 或 正規表現 为样板，**用它来展示大屏宽布局如何解决拥挤问题**）
   - ⑤ 信任/合规页（隐私政策类长文排版）
4. **组件展示页（Component Gallery）**：把 §4 列出的所有组件及其全部状态集中展示在一个 HTML 页面里。
5. **响应式说明**：上述页面在 **1920 / 1440 / 768 / 375** 四个宽度下的布局示意，**特别标注大屏两栏拥挤问题的解决方案**。
6. （可选）**设计说明 README**：你的设计理念、令牌命名规则、以及"如何把这套设计套用到剩余 23 个工具页"的指南。

## 7. 附录：工具页真实区块骨架（参考，不限制风格）

以现有"消費税・割引計算器"页为例，让你了解一个工具页要排哪些块（HTML 结构示意，**样式随你重做**）：

```
page-hero
 ├ 面包屑：ホーム ／ 消費税・割引計算器
 ├ H1：消費税・割引計算器
 └ 副标题：税抜・税込・割引後の価格を、入力するだけで瞬時に計算します。

calc-card
 ├ Tab 切换条：[税込計算][税抜計算][割引計算][複数商品]
 └ 当前 Tab 面板：
     ├ 表单组：税抜価格（円）[ 数字输入 ]
     ├ 按钮式单选：(●)10%（標準） ( )8%（軽減）
     └ 结果框：
         ├ 标签：税込価格
         ├ 主结果（大数字）：¥1,100
         └ 明细行：税抜価格 ¥1,000 ／ 消費税額 ¥100（红色）

广告位（結果直下）

howto「使い方」
 ├ H2：使い方
 ├ 要点列表（各计算模式说明）
 ├ 注意事项段落（端数切り捨て等）
 └ 免责声明框：※ 計算結果はあくまで参考値です。

RelatedTools：4 个关联工具小卡片（图标 + 名称）

FAQ：2~3 组 Q&A

广告位（コンテンツ下部）

分享按钮条：X / LINE / Facebook / はてブ / コピー
```

> 复杂工具（如 Markdown）则把 calc-card 换成"左编辑 / 右预览"的双栏宽布局；正規表現换成"上方 pattern 输入 + 下方文本框 + 匹配高亮"。这些就是 §3.4 要重点解决的大屏布局场景。
